# SillyTavern 小说转角色卡

把小说正文交给当前连接的模型，自动整理成可导入 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 的 **PNG 角色卡**，并顺带提取**世界书**。

- 生成的 PNG 内嵌标准 `chara`（Character Card V2）与 `ccv3`（Character Card V3）区块，拖回酒馆即可导入
- **像素数据不重新编码**：只在 IHDR 之后插入两个 `tEXt` 区块，不碰 IDAT，画质无损、体积几乎不涨
- **长篇小说自动分卷**：识别章标题，按卷数或字数切开，逐卷出卡，跑砸了只需重跑那一卷
- **主角 / 配角分级**：判定重要程度，主角出完整人设、配角出精简卡，各自按配额取用
- **可独立配置 API**：扫描和出人设可以用另一个模型（比如便宜模型扫描 + 强模型出人设），带连通性测试
- **独立开关与独立窗口**：面板顶部一个启用开关（关掉即置灰停用）；可把整个面板提升为可拖动的浮动窗口，位置自动记住
- **中途保存**：正文、分卷、候选角色、已出卡档案、世界书一并存进浏览器 IndexedDB，随时恢复继续
- 世界书既能单独导出 JSON 导入世界书库，也能内嵌进角色卡（`character_book`）
- 复用酒馆当前的模型连接（`generateRaw`），不写聊天记录，也不走角色卡 / 预设的提示词注入

## 安装

### 方式一：放进扩展目录（推荐）

```bash
cd <SillyTavern>/data/extensions/third-party
git clone https://github.com/misa1ink/SillyTavern-Novel-To-Card.git
```

然后刷新酒馆网页，打开「扩展」（拼图图标）→「小说转角色卡」，在面板底部展开。

### 方式二：手动拷贝

把本仓库的文件（`manifest.json`、`index.js`、`style.css`、`src/`）放进：

```
<SillyTavern>/data/extensions/third-party/SillyTavern-Novel-To-Card/
```

## 用法

1. **载入文本** —— 点「选择文件」导入 `.txt / .md / .jsonl`，或直接把正文粘贴进文本框。填一下作品名（可选，会进提示词）。
2. **（长篇强烈建议）分卷** —— 见下一节。短篇可以跳过。
3. **分析人物** —— 分段扫描出场人物，并合并同一角色的不同称呼。开了「区分主角与配角」的话，这一步会顺带分级并按配额勾选（见「角色分级」一节）。
4. **生成角色卡** —— 逐角色出结构化档案 → 构建卡片 → 生成 PNG。每个角色有三个按钮：下载 PNG、下载卡片 JSON、手动导入角色列表。

## 角色分级（主角 / 配角）

开了「区分主角与配角」之后，「分析人物」会多调一次模型，把人物判成三档：

| 档位 | 含义 | 默认配额 | 档案 |
| --- | --- | --- | --- |
| **主角** | 核心视角或主要推动者，贯穿全书 | 最多 3 个 | 完整（含外貌、能力、背景、备选开场白） |
| **主要配角** | 戏份多、影响主线，但不是核心视角 | 最多 6 个 | 完整 |
| **次要配角** | 偶尔出场、功能性角色 | 计入配角配额 | **精简**（只留撑得起一张卡的信息） |

- 结果按「主角 → 主要配角 → 次要配角」排序，**超出配额的角色自动取消勾选**（不会删除，你可以手动勾回来）
- 开了「配角用精简档案」后，配角的证据片段数和输出 token 都会减半，卡片更干净也省钱
- 角色列表里可以点「判定主角/配角」按钮单独重跑分级
- 分级失败不会中断流程，会退化为「全部按主要角色处理」

## 独立开关与独立窗口

面板顶部右上角：

- **启用** 开关 —— 关掉后面板整体置灰、所有按钮不再响应，**顶栏入口整块隐藏**（不是变暗，不留空白占位），面板上会显示「已关闭（顶栏入口已隐藏）」提示。跑长篇时不想被误触就关掉它
- **独立窗口** —— 把面板提升成可自由拖动的浮窗，方便一边看酒馆聊天一边操作

窗口行为：

- 拖动标题栏移动，位置和大小记在设置里，重开酒馆自动恢复原位
- 点窗口里的「收回」或关闭按钮回到扩展设置面板
- 顶栏（拼图图标旁边）多了一个卡片图标，点它可直接开关这个浮窗；**插件关闭时这个入口会一起消失**

## 中途保存

长篇小说一次跑不完很正常。「存档与进度」一节提供：

- **立即存档** —— 把当前进度整体存下来
- **自动存档** —— 默认开启，会在「分卷完成 / 人物分析完成 / 角色卡生成完成」三个节点自动存一次（同名覆盖，不会堆积）
- **恢复** —— 存档列表里点「恢复」即可接着跑；每份存档可单独删除

一份存档包含：小说正文、分卷结果与当前卷、候选角色（含分级与勾选状态）、已生成的卡片档案、世界书条目、最近日志。

几点说明：

- 存在浏览器 **IndexedDB** 里（约 6MB 的正文也没问题）。**不用 localStorage** 是因为它通常只有 5MB 上限，塞 300 万字会直接爆
- 存档**不含生成的 PNG 图片**——那是二进制大对象，塞进 JSON 会让存档膨胀十倍以上，而且重开酒馆后卡片通常已经导入角色列表了。恢复后如需图片，重新点「生成角色卡」即可（角色和分级都会保留，不用重新分析）
- 存档是**本机浏览器的**，不会跨设备同步；换设备请用导出角色卡 / 世界书文件的方式搬运

## 独立 API 配置

高级设置里可以把「分析用的模型通道」切到 **独立 API**，填自己的地址、Key、模型名，和酒馆当前连接互不干扰。典型用法：

| 场景 | 配置 |
| --- | --- |
| 省钱 | 独立 API 填**便宜模型**跑扫描和分级 |
| 质量优先 | 独立 API 填**强模型**出人设 |
| 酒馆本身用的模型不适合做结构化输出 | 切到独立 API 换一个擅长 JSON 的模型 |

- 地址填到**版本段**即可（如 `https://api.deepseek.com/v1`），服务端会自己拼 `/chat/completions`
- 支持 `temperature` / `top_p` 覆盖，留空则跟随默认
- 点 **「测试连接」** 会发一个最小请求，直接告诉你通不通、耗时多少、返回了什么——不用等到跑长篇才发现填错
- 请求走酒馆后端转发（`/api/backends/chat-completions/generate`），与普通生成同源同形；**Key 只存在本地设置里**
- 兼容中转站：即使对方无视 `stream: false` 仍返回 SSE，也能正确解析出文本

## 分卷（长篇小说必读）

整本书一次跑，请求数、费用和失败面会一起线性放大。分卷后每卷独立出卡、独立出世界书，跑砸了只需要重跑那一卷。

两种分卷方式：

| 方式 | 说明 |
| --- | --- |
| **按每卷字数** | 指定每卷多少字（默认 50 万），插件自己算卷数 |
| **按固定卷数** | 指定切成几卷，插件平分成那么多卷 |

再配合「**优先按章节边界切**」：开启后会识别 `第X章 / 第X回 / 第X节 / 序章 / 楔子 / 番外 / Chapter N` 等章标题，把切点放在章与章之间，**不会把一句话切成两半**。识别不到章标题（或标题少于 3 个）会自动退回按段落边界切。

点「预览分卷」后会列出每一卷的标题、字数和预估扫描请求数。点某一卷即可切换，**「分析人物」「生成角色卡」只作用于当前卷**——已出卡的卷会标记「已出卡」和卡片张数。

### 以 300 万字为例

- 建议每卷 30–50 万字 → 约 6–10 卷
- 每卷扫描请求约 50–85 次，**逐卷跑**，不要一次跑全书
- 每卷的世界书会单独导出，文件名带卷号（如 `小说·第 3 卷世界书.json`），在酒馆里可以多个世界书同时启用
- 先跑第 1 卷验证质量，满意再继续

改了「分段字数」或任何分卷参数后，之前的分卷结果会自动失效并提示重新预览——避免拿错卷跑。

## 高级设置

| 设置 | 说明 |
| --- | --- |
| 分段字数 | 每段送给模型的字数。中文建议 4000–8000；模型上下文小就调小 |
| 请求并发 | 人物扫描阶段的并发数。容易触发限流就降到 1–2 |
| 最多角色数 | 按出场量排序后取前 N 个角色 |
| 每角色证据段数 | 每个角色从全文里挑多少段原文作为提取依据，越大越准也越费 token |
| 角色卡版本 | V3（推荐）/ V2 / 两者都要。无论选哪个都会带一份 V2 视图给老前端 |
| 区分主角与配角 | 多调一次模型做分级，按配额挑选 |
| 主角 / 配角最多几个 | 分级后的配额，超出的自动取消勾选 |
| 配角用精简档案 | 配角只生成核心字段，省 token 也让卡片干净 |
| 模型通道 | 酒馆当前连接 / 独立 API |
| 启用 | 插件总开关，关闭后所有操作停用 |
| 自动存档 | 在关键节点自动保存进度 |
| 缩放并重建底图 | 默认关闭。关着时若底图本身是 PNG 会原样使用，避免 JPEG 转 PNG 体积暴涨 |
| 世界书内嵌进角色卡 | 卡里带 `character_book`，导入时酒馆会提示是否转成独立世界书 |
| 额外提示词 | 追加到每个角色的提取要求，例如「保留原著口癖」 |

## 成本参考

一部 20 万字的小说，默认参数下大约：

- 人物扫描：约 30 次请求（每段一次）
- 单角色档案：每个角色 1 次（含最多约 1.4 万字证据）
- 世界书：1 次（抽样 8 段）

即「10 个角色 + 世界书」约 41 次请求。建议先拿短篇试跑，确认提取质量符合预期再上长篇。

## 工作原理

```
小说文本
  ├─ 分卷（可选）：按章标题 / 段落 / 句子边界切，逐卷独立处理
  ├─ 分段（按段落边界切，段间留少量重叠，保护跨段对话）
  ├─ 阶段 A：逐段扫描出场人物   → 合并同名/别名角色（按出场量排序）
  ├─ 阶段 A2：角色分级（可选）  → 主角 / 主要配角 / 次要配角 + 配额挑选
  ├─ 阶段 B：为每个角色从全文收集最相关的原文片段（按命中密度取，按原文顺序排）
  ├─ 阶段 C：逐角色出结构化档案 → 主角走完整 schema，配角走精简 schema
  └─ 世界书：抽样若干段 → 条目化、过滤无效触发词
        ↓
   PNG（IHDR 后插入 chara / ccv3 两个 tEXt 区块，IDAT 原样保留）
  世界书 JSON（可直接导入世界书库）
```

模型通道可以整体切到独立 API（`/api/backends/chat-completions/generate` 转发），
也可以留在酒馆当前连接（`generateRaw`）。两种通道共用同一套提示词与 JSON 容错解析。

模型输出一律走 JSON 解析，并带容错：代码块围栏、前后寒暄、尾随逗号、中文引号、被截断的数组都能救回来。

## 目录结构

```
manifest.json        扩展清单
index.js             面板 UI、流程编排、分卷交互、分级配额、导入酒馆
style.css            面板样式（跟随酒馆主题变量）
src/png-card.js      PNG 区块读写、CRC32、base64、图片处理、下载
src/card-builder.js  V2/V3 卡结构组装
src/prompts.js       提示词模板（含分级与两种详细度）与模型输出 JSON 解析
src/ai.js            分段、人物合并、证据收集、分级、模型调用（酒馆通道 / 独立 API）
src/splits.js        长篇小说分卷（章标题识别、卷数与字数切分）
src/persist.js       IndexedDB 存档（写入 / 列出 / 读取 / 删除）
src/world-builder.js 世界书条目规范化与两种导出结构
tests/run.mjs        自测（83 项，不依赖酒馆运行时）
tests/harness.mjs    加载与交互测试（19 项，真正求值 index.js）
tests/fixture.mjs    现场生成测试用的合成角色卡
tests/fake-indexeddb.mjs  内存版 IndexedDB，供存档测试使用
```

## 自测

无需安装任何依赖，也不需要酒馆在运行：

```bash
node tests/run.mjs                                  # 83 项单元测试
node --experimental-vm-modules tests/harness.mjs    # 22 项加载与交互测试
```

`tests/run.mjs` 覆盖：PNG 区块写入与读回、CRC 自洽、IDAT 像素不变、base64 中文往返、
卡片字段组装、世界书结构、模型输出 JSON 容错（截断 / 围栏 / 中文引号）、分段与人物合并、
分卷（章标题识别 / 不丢字 / 卷数精确 / 下限保护）、独立 API 请求契约与错误处理、档位归一。

`tests/harness.mjs` 会在 Node 里用**最小 DOM + 桩模块 + 内存版 IndexedDB 真正求值 `index.js`**，
断言：面板能挂载、控件都渲染出来、事件绑定确实写回设置、总开关能拦住所有入口、
**顶栏入口在关闭时整块隐藏、启用后恢复**、浮窗能正确搬运面板主体并回到抽屉、
存档写读往返不丢字段、同名覆盖、删除后读不到。

它存在的意义：曾经出现过「语法完全合法、只在酒馆加载时抛 SyntaxError」的 bug，
纯语法检查抓不到——这个 harness 把「扩展能否被加载」变成可自动验证的检查。

## 兼容性

- 目标环境：SillyTavern 1.12+（含 TauriTavern 等封装版）
- 生成走 `getContext().generateRaw()`，建卡走 `POST /api/characters/create`，
  世界书走 `saveWorldInfo()` —— 都是酒馆公开接口
- 纯前端扩展，零依赖、无构建步骤

## 已知限制

- 只接受纯文本（`.txt / .md / .jsonl`），不解析 EPUB / PDF。需要的话先用别的工具转成文本。
- 提取质量取决于所用模型。弱模型容易编造原文没有的设定，可在「额外提示词」里加约束。
- 长篇（30 万字以上）的扫描请求数会线性增长，注意 API 费用。
